# 湖北省日前电价预测实验状态

更新日期：2026-05-02

## 1. 当前实验目标

本项目用于湖北省电力现货市场日前电价预测，目标是利用市场边界、气象和历史价格等多源异构数据，预测 **T+1 日 24 个小时的实时出清价格**。

当前主线已收敛为 **Direct 多步预测策略**：

```text
H00: f_00(X_00) -> Price_H00
H01: f_01(X_01) -> Price_H01
...
H23: f_23(X_23) -> Price_H23
```

即 24 个预测步长分别训练 24 个独立模型，每个小时可以单独选特征、单独调参、单独保存和评估。

## 2. 预测场景说明

预测场景本身没有变化。

在 T 时间点进行预测时，业务假设仍然是：

- **预测目标**：T+1 日 24 点实时出清价格。
- **历史实时价格**：只使用 T-2 及之前的实时价格，避免使用 T 或 T+1 未来信息。
- **日前披露数据**：使用 T 日已经披露的 T+1 日市场边界信息。
- **气象数据**：使用 T+1 日对应的气象预报或已整理后的可用气象输入。

需要特别说明的是：**数据预处理阶段对部分非价格类实际/实时字段做了日前值填充**。这不是改变预测场景，而是为了让训练数据中的输入字段与真实预测时可获得的信息保持一致。

具体理解：

- 预测时无法提前获得 T+1 日的真实实时负荷、新能源实际出力、水电实际出力、联络线实际潮流等。
- 因此在预处理阶段，非价格类实时/实际市场边界字段可用对应日前披露值填充，用来模拟预测时可获得的输入。
- **实时价格目标不做这种填充**，仍然作为要预测的真实目标值。
- **日前价格不可用，已经在预处理阶段删除，后续特征工程和训练均不使用日前价格。**
- Direct 特征工程中，实时价格滞后只取 T-2 日同一小时，避免数据泄露。

旧的 global / 多输出策略已删除：


删除原因：旧 global 流程主要依赖 `MultiOutputRegressor` 或统一封装接口，形式上一次输出 24 点，但多数模型内部仍是多个独立子模型，不能真正建模 24 个小时之间的联合关系，也不利于逐小时独立调参。当前实验更适合直接采用 Direct 策略。

### 3.1 策略扩展预留

当前主策略是 `direct`，但框架已预留多策略对比实验入口：

```text
direct      已实现：24 个独立单输出模型，每个小时独立训练和调参
recursive  预留：一步或短步长模型迭代预测，后续步长可使用前序预测值
mimo        预留：真正联合预测 24 小时价格曲线的多输出模型
```

策略注册文件：

```text
code/strategy_registry.py
```

设计原则：

- 当前命令默认 `--strategy direct`。
- `recursive` 和 `mimo` 目前只作为预留策略名，调用时会提示尚未实现。
- 后续新增策略时，应新增独立策略文件，例如 `train_recursive.py` 或 `train_mimo.py`，避免把多种策略混写进 Direct 训练脚本。
- 各策略共用 `model_factory.py`、`utils/metrics.py` 和统一结果目录规范。

- 保留实时价格作为预测目标。

## 5. Direct 特征工程

特征工程文件：

```text
code/feature_engineering_direct.py
```

每个小时生成一个独立特征文件：

```text
data/features/direct/features_H00.csv
...
data/features/direct/features_H23.csv
```

每个文件中：

- 一行代表一个目标日期在某个小时的预测样本。
- `预测日期` 表示目标日期。
- `Price_Hxx` 是该小时的实时价格目标。
- 其他列为该小时模型可使用的输入特征。

### 5.1 当前 Direct 特征设计

时间特征：

- 月份
- 星期
- 是否周末
- 季度

历史价格特征：

- `滞后2天_Hxx_价格`
- `滞后3/4/7/14天_Hxx_价格`
- `滞后2天_Hxx_前1h/后1h_价格`
- T-2 日全日价格形态统计，以及 T-2 及以前同小时滚动统计。
- 只使用 T-2 及之前的实时价格，规避 T-1、T 或 T+1 价格信息造成的数据泄露风险。

可用市场边界窗口特征：

- 当前小时
- 滞后 1h
- 未来 1h
- 原始市场边界：系统负荷、风电、光伏、水电、联络线、非市场化机组等。
- 衍生市场边界：新能源出力、净负荷、剩余负荷、市场化缺口、供需覆盖率、各类占负荷比例。
- 相邻小时爬坡：当前减滞后 1h、未来 1h 减当前。
- 目标日市场日内形态：均值、标准差、最小值、最大值、当前小时相对日均值和日内位置。

特征名前缀示例：

```text
当前_市场_系统负荷
滞后1h_市场_系统负荷
未来1h_市场_系统负荷
市场变化_当前减滞后1h_净负荷
市场日形态_H07_市场化缺口_日内位置
```

气象窗口特征：

```text
当前_气象_...
滞后1h_气象_...
未来1h_气象_...
```

### 5.2 特征选择

统一由以下文件控制：

```text
code/feature_config.yaml
```

当前支持通过特征组和正则模式选择输入，例如：

```yaml
feature_groups:
  direct_market_window:
    patterns:
      - "^(当前|滞后1h|未来1h)_市场_"
      - "^市场变化_"
      - "^市场日形态_"
```

不同模型可以在 `model_features` 中配置不同特征组和是否标准化。

## 6. 模型方案

模型创建已从旧 `models/` 目录改为轻量工厂：

```text
code/model_factory.py
```

当前支持：

```text
lightgbm
lightgbm_smape_probe
xgboost
random_forest
ridge
lasso
```

设计原则：

- 训练脚本只关心 Direct 流程，不关心具体模型库的导入细节。
- 需要哪个模型，就在 `model_factory.py` 中按需导入对应库。
- 每个小时单独搜索参数并保存 `metadata_Hxx.json`。
- `lightgbm_smape_probe` 是本轮实验沉淀的显式探针参数组，仍然使用 LightGBM，但允许每个小时使用不同 objective/quantile alpha。它不覆盖标准 `lightgbm`，便于区分常规训练和探针型结果。

## 7. 训练、评估与预测

统一入口：

```text
code/main.py
```

### 7.1 生成特征

```bash
python code/main.py features --strategy direct
```

### 7.2 训练模型

```bash
python code/main.py train --strategy direct --model lightgbm --n-iter 20
```

只训练部分小时：

```bash
python code/main.py train --strategy direct --model lightgbm --hours 0 8 12 18 --n-iter 20
```

不做随机搜索，直接使用默认参数：

```bash
python code/main.py train --strategy direct --model ridge --n-iter 0
```

### 7.3 评估模型

```bash
python code/main.py evaluate --strategy direct --model lightgbm
```

只评估部分小时：

```bash
python code/main.py evaluate --strategy direct --model lightgbm --hours 0 8 12 18
```

### 7.4 预测

```bash
python code/main.py predict --strategy direct --model lightgbm --date 2025-03-26
```

如果目标日期在已生成特征中不存在，预测脚本会使用最新可用特征行，并在日志中提示。

### 7.5 一键流程

```bash
python code/main.py run-all --strategy direct --model lightgbm --n-iter 20
```

### 8.1 LightGBM 实验进展

本轮实验遵守约束：**不使用日前价格**。新增的有效输入来自 T-2 及之前的历史实时价格、预处理后的可用市场边界、市场边界衍生量与市场爬坡特征。

## 9. 当前框架优点

- 项目主线清晰：只保留 Direct 策略。
- 删除了旧 global 和 `models/` 复杂封装。
- 每个小时单独建模，更符合电价峰谷差异和小时规律。
- 每个小时可独立调参、保存、分析误差。
- 特征输入仍由单一 YAML 文件统一控制。
- 模型创建集中在轻量 `model_factory.py`，后续加模型更简单。
- 策略层已预留 `recursive` 和 `mimo`，后续做多策略对比时不需要再重构入口。

## 10. 后续建议

短期建议：

- 对 `lightgbm_smape_probe` 做滚动回测，确认探针参数是否只对当前测试月有效。
- 重点分析 H08-H16 午间低价/尖峰时段，当前这些小时仍是整体 sMAPE 的主要来源。
- 输出每小时真实值/预测值曲线和残差分布，检查低价分母效应、尖峰偏差和系统性高估/低估。

中期建议：

- 在 `feature_config.yaml` 中为峰时段和谷时段设计不同特征组。
- 加入节假日、工作日类型等外部日历特征。
- 对价格尖峰单独做误差分析。

长期建议：

- 若后续确实需要建模 24 小时价格曲线整体形态，可在 `mimo` 策略下新增真正的 MIMO/Seq2Seq 深度模型，而不是恢复旧 `MultiOutputRegressor` 式 global 流程。
- 若后续希望研究误差传播和滚动预测，可在 `recursive` 策略下新增迭代式特征工程、训练和预测脚本。
